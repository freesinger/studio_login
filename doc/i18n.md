# 国际化

前后端统一使用 i18next，支持 `zh-CN`、`en`、`ja`。词条存放在 `public/locales/`，使用固定语义 key；中文、英文、日文均为 value。不存在中文源文案匹配或 `server-keys.json` 注册表。

## 添加文案

1. 在三个语言文件中添加同名 key，例如 `studio.httpError`。使用具名插值 `{{status}}`，不要使用位置参数或把整句中文作为 key。
2. 前端调用 `t('studio.httpError', { status: 503 })`；静态 HTML 使用 `data-i18n`、`data-i18n-placeholder`、`data-i18n-title`、`data-i18n-aria-label`。
3. 服务端使用 `message('studio.httpError', { status: 503 })` 构造消息，交给 `AppError`；需要直接输出时使用 `translate(key, locale, params)`。
4. 执行 `npm run i18n:types` 更新生成的 key 和参数类型，再运行 `npm run typecheck` 与 `npx vitest run test/i18n.test.ts`。类型检查会拒绝过期的生成文件、无效 key、缺失或错误的参数名称。覆盖测试还会核对三种语言 key 和占位符一致性，以及前端调用参数。

文案中的用户输入直接作为字符串参数保留；需要翻译的系统概念使用嵌套 `message(...)`。不要遍历 API 数据对象并猜测哪些字符串需要翻译。

## 语言选择和安全输出

语言入口位于已有的页面标题区或登录卡片中，不占用额外顶部栏。URL 的 `lang` 参数优先，其次为 localStorage 中的选择，默认中文。切换时重新加载当前页面以刷新服务端消息，保留当前工作台栏目；存在未提交表单时提醒用户。

浏览器通过同源 `/vendor/i18next.js` 加载 npm 安装的 i18next ESM 文件，不依赖 CDN。中文资源作为 fallback，所选其他语言加载失败时回退中文。API 请求和 CSV 下载携带 `Accept-Language`，服务端按语言质量权重选择支持的语言，并返回 `Content-Language` 与 `Vary: Accept-Language`。

语言资源请求有 5 秒超时；中文资源失败不会阻断可用的所选语言。所选语言与中文均不可用时，尝试剩余受支持语言；全部失败则显示错误并保持登录按钮禁用。登录按钮只在提交处理注册后启用，表单也显式使用 POST，避免初始化未完成时将凭证提交到 URL。

i18next 不负责 HTML 转义；文本使用 textContent，动态 HTML 的用户数据在渲染边界通过 escapeHtml 转义。数字、日期按所选语言格式化；账期和业务时区仍维持原有规则。

## 服务端错误和持久化

业务异常携带稳定 `code`、`messageKey` 和 `messageParams`，HTTP 响应保留已翻译的 `message`，兼容现有前端。每次翻译显式传入语言，不修改共享实例的当前语言。Zod 使用对应语言的官方错误映射，CSV 行校验在扁平化字段路径之前翻译。

多语言范围限于页面和即时提示，不新增数据库字段，也不改变持久化格式。同步失败仍保存原始诊断，查询配置组和子账号时原样返回，不随语言选择重新翻译。用户名称、配置内容、第三方原始诊断和内部协议固定字符串保持原值。运行日志使用中文规范文案，不随请求语言改变。

## 验证

`test/i18n.test.ts` 覆盖词条、参数、静态标记、语言协商、并发隔离、HTTP 错误和 CSV 校验。另有测试确保同步错误仍按原有格式保存，不携带语言元数据。

`test/i18n-browser.test.ts` 在隔离环境执行前端语言模块，覆盖资源失败、损坏、超时和语言降级；登录按钮与回车提交的原生行为还需浏览器验证。

集成测试必须使用专用数据库，通过 `STUDIO_LOGIN_TEST_DATABASE_URL` 指定；不得指向开发或生产数据库。浏览器验证与 mock 上游测试不等同于真实 Studio 服务端到端验证。
